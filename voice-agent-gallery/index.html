Voice Agent Example Gallery

22 customer service scenarios you can build with Copilot Studio, Contact Center Intelligence, Dynamics 365 Contact Center, Teams Phone and Microsoft Foundry.

Note: Based on Microsoft Learn documentation as of October 31, 2026. Many of the capabilities used here are in preview.

1. How to read this gallery

Each scenario has user stories ("As a ... I want ... so that ..."), the events it relies on (harness events in Copilot Studio, or real-time API events in Foundry) and an implementation outline.

4. Scenarios

Scenario 1: Order status and returns (base agent)

User stories

  • As a caller, I want to say my order number naturally and hear where my parcel is, so that I don't wait for a person.
  • As a caller who goes quiet, I want the agent to check that I'm still there instead of hanging up.
  • As a service manager, I want a short survey at the end of every self-service call.

Acceptance criteria: Caller number recognised, order confirmed, status read back, return started through a workflow if needed, one-question survey at the end.

Events

Conversation Start (hydrate System.Activity.From.User for the caller number), Silence Detection, End of Conversation (survey logic).

Implementation outline

  1. Create a Customer Conversation agent in Copilot Studio or the CCI portal. Primary agent plus sub-agents "Order status" and "Returns".
  2. Tools: connector or REST API for order lookup, workflow for creating the return.
  3. Voice tuning: use Server VAD for short answers like order numbers (suggested start: threshold 0.6, prefix padding 300 ms, silence 750 ms), with confirmation prompts for read-back. Use Semantic VAD for open questions.
  4. Test in the Preview tab, then build an Evaluate test set with 20 to 30 spoken order-number variants.
  5. Deploy: demo website first, then the Dynamics 365 Contact Center channel from the CCI portal (Omnichannel Admin).

Scenario 2: Secure account change with voice biometrics

User stories

  • As a returning caller, I want to be recognised by my voice, so that I'm not asked security questions every time.
  • As a new caller, I want to be asked for consent before my voiceprint is stored.
  • As a fraud lead, I want a one-time passcode fallback when voice confidence is low.

Events

Biometric enrollment consent, Speech collection for biometric enrollment and authentication, SMS One Time Passcode.

Implementation outline

  1. Enable Voice Authentication on the Security tab of Shared Settings, and Biometric Authentication in Voice capabilities.
  2. Identity lookup: phone number and/or account number against the Dataverse Contact or Account table. Pick the authentication policy level.
  3. In the CCI portal, set consent, confidence thresholds, retry limits, fallbacks and human-review rules.
  4. Gate "Change address" and "Change bank details" skills behind successful authentication.
  5. Add the "Biometric voiceprint unenrollment" skill.
  6. Do a DPIA and legal review of the consent wording. Voice biometrics is special category data under GDPR.

Scenario 3: Billing dispute with warm handoff

User stories

  • As a frustrated caller, I want to reach a person at any time without repeating my story.
  • As a representative, I want the full transcript and call reason before I say hello.

Events and tools

Escalate tool (Escalate to Customer Engagement), End of Conversation.

Implementation outline

  1. Add the Escalate tool. Define implicit triggers in the instructions (repeated anger, disputed amount above a threshold, third failed explanation).
  2. On handoff the whole conversation goes to the engagement hub, which finds the best available representative.
  3. Route disputes to a billing queue in Dynamics 365 Contact Center.
  4. For legacy PBX scenarios with direct routing, carry context in SIP UUI or X-headers.
  5. Track resolution rate, escalation rate, resolution time, escalation time and average sentiment on dashboards.

Scenario 4: Returning caller, call to chat continuity

User stories

  • As a customer who called yesterday, I want today's chat to know my open issue.
  • As a product owner, I want stored context to expire on its own.

Events

Conversation Start using memory variables (pastOpenIntentList, pastConversationSummary).

Implementation outline

  1. Turn on Memory at agent level (applies to the root and all child agents).
  2. Reference memory variables in the greeting instructions.
  3. Configure a shared contact identifier so phone and authenticated web chat map to the same customer.
  4. Retention is 30 days of short-term context. Document this in the privacy notice.

Scenario 5: Multilingual service line

User stories

  • As a bilingual caller, I want to switch from German to English mid-call without a transfer.
  • As an operations lead, I want escalations to land with a representative who speaks the caller's language.

Implementation outline

  1. Use Customer Assist Agent with speech-to-speech, which supports dynamic language switching within one conversation. Check the supported language list for your locales.
  2. Pass the detected language into escalation context and route to language-specific queues in Dynamics 365 Contact Center.

Scenario 6: Clinic or branch front desk on Teams Phone

User stories

  • As a patient, I want to book or move an appointment by phone outside opening hours.
  • As a Teams admin, I want the agent to transfer to the right call queue without hardcoded numbers.

Implementation outline: choose one of two paths

Path A: Teams Phone Agent + standard Copilot Studio voice agent

  1. Teams Phone Agent handles Q&A and appointments (Microsoft Bookings integration in Teams admin center).
  2. For custom workflows, hand off to a Copilot Studio voice agent that uses classic orchestration and a basic voice agent.
  3. Use tags to pass transfer targets (call queues, auto attendants) without hardcoding.
  4. Teams admin center: resource account type "AI Agent", Teams Phone Resource Account license, phone number (Calling Plans, Operator Connect or Direct Routing), link the agent.
  5. Set agent authentication to "No authentication" for this channel.

Path B: Customer Conversation harness agent deployed to the Teams Phone channel

  1. Build the agent on the harness and deploy it to the Teams Phone channel from the Deploy page.
  2. Use "Escalate to Teams Phone" to transfer to people or queues.

The Copilot Studio and Teams Phone integration entered public preview on October 22, 2026 and may need tenant enablement.

Scenario 7: Proactive outbound callback (Foundry)

User stories

  • As a customer who asked for a callback, I want the agent to call me, verify me and finish the request.
  • As a developer, I want full control of barge-in, tool calls and model choice in code.

Events (Voice Live API)

Client events session.update, input_audio_buffer.append, input_audio_buffer.commit, response.create, response.cancel, conversation.item.truncate; server events for transcripts, audio deltas and function calls.

Implementation outline

  1. Create a voice-based prompt agent in Foundry.
  2. Configure native telephony (Teams Phone extensibility or Twilio). Foundry handles inbound and outbound calls.
  3. Function calling for CRM lookups and case updates.
  4. Pin the agent version (production stable, development tests newer versions). Use Entra ID auth, since agent mode does not support key-based authentication.
  5. Enable truncation-aware handling so stored history matches what the caller actually heard.
  6. Optional: connect this Foundry agent into a Customer Conversation orchestration via "Connect existing agent". The harness then provides events, escalation and memory.

For application-managed telephony, the Call Center Voice Agent Accelerator with Azure Communication Services is an alternative. Foundry voice agents are in preview.

Scenario 8: Keep Genesys, add AI

User stories

  • As a CIO, I want AI self-service and voice biometrics without replacing our Genesys contact center.

Implementation outline

  1. Connect Genesys Cloud in the CCI portal (voice connector, chat connector, AudioHook for voice biometrics).
  2. Deploy the agent from Scenarios 1 to 3 to the Genesys channel.
  3. Other platforms (Cisco, Avaya, others) use the universal connector or "Bring your own".

Scenario 9: Outage broadcast without republishing

User stories

  • As a service lead, I want to put an outage message on the line in minutes, without a developer.

Events

Conversation Start.

Implementation outline

  1. Dataverse table "Broadcast messages" (text, language, active from, active to).
  2. Power Apps model-driven or canvas app for service leads.
  3. In Conversation Start, call a tool (connector or workflow) that reads the active message and plays it before intent classification. Events are topics, so this follows the same rule manager pattern used for IVR agents in Dynamics 365 Contact Center.
  4. Measure the added latency at call start.

Scenario 10: Supervisor quality assurance and error telemetry

User stories

  • As a QA lead, I want every call scored, not a 2% sample.
  • As an operations engineer, I want each failure logged with the conversation ID.

Events

On Error.

Implementation outline

  1. Configure quality assurance in the CCI portal. Use the real-time and historical dashboards.
  2. Edit the On Error event to log to Azure Analytics with agent version, tool name and error details.
  3. Add failed conversations to Evaluate test sets as regression cases.

Scenario 11: Insurance first notice of loss (FNOL)

User stories

  • As a policyholder after a car accident, I want to report the claim by phone at any hour and get a reference number.
  • As a claims handler, I want structured claim data, not a free-text note.

Implementation outline

  1. Foundry voice agent with function calls that fill a claim object (incident description, location, parties involved, policy number).
  2. Write the claim to Dynamics 365 or the claims system, and read back the reference number.
  3. Escalate to a person if anyone is injured or the caller is distressed.
  4. Use Microsoft's open-source call-center-ai repository as design inspiration. It is not a supported product.

Scenario 12: Call queue overflow to an AI agent

User stories

  • As a caller during a peak, I want help from an AI agent instead of waiting 20 minutes.

Implementation outline

  1. In the Teams call queue, set exception handling for: no agents logged in, too many callers waiting, or wait time over the limit.
  2. Redirect to a Teams Phone Agent (Scenario 6) that handles the top three intents.

Scenario 13: Spam and robocall screening

User stories

  • As a reception team, we want junk calls filtered before they reach a person.
  • As a compliance officer, I want callers told they are talking to AI.

Implementation outline

  1. Configure spam detection for the Teams Phone Agent (PowerShell).
  2. Configure the AI disclaimer (Teams admin center or PowerShell).
  3. Set a maximum call length with a disconnect message as a safety limit.
  4. Optional: automatic recording for review.

Scenario 14: AI keeps assisting after handoff

User stories

  • As a representative, I want the AI that took the call to keep feeding me answers while I talk to the customer.

Implementation outline

  1. Customer Assist Agent resolves autonomously, recognises when a human is needed and transfers with full context to Dynamics 365 Contact Center.
  2. After handoff it continues to assist the representative in real time.

Scenario 15: Expert consult and AI consult during a live call

User stories

  • As a first-line representative, I want to pull in a product specialist through Teams without transferring the customer.
  • As a representative, I want an AI agent to read a mandatory disclosure or verify a PIN, then hand the call back to me.

Implementation outline

  1. Teams expert collaboration during live engagements in Dynamics 365 Contact Center.
  2. Consult with AI agents: turn the setting on, make a voice-enabled AI agent available for consult. The representative selects Consult, then the AI Agents tab. The AI agent runs its workflow (disclosure, consent capture, PIN check) and leaves. Options: keep the representative on hold, pause recording and transcription during consult.
  3. Configure handoff back to a representative in the agent topic.

Voice-enabled AI agents join a call through the consult option. This is a preview feature.

Scenario 16: Proactive outreach campaign

User stories

  • As a customer, I want a call telling me my delivery is late, with the option to rebook right away.
  • As a campaign manager, I want retries, frequency limits and opt-outs respected.

Implementation outline

  1. Dynamics 365 Contact Center proactive engagement: outbound voice workstream, audience via file upload, CCaaS API, MCP (preview) or Customer Insights journeys.
  2. Add a standard Copilot Studio voice IVR agent (voice IVR template) to the outbound workstream (AI-led engagement).
  3. Enable the answering machine detection system topic and personalise the voicemail message.
  4. Pass customer and campaign context into the agent with global variables ("External sources can set values"). Send outcomes back with variables marked "External sources can receive the value". They appear in the proactive delivery table.
  5. Your organisation must honour consent and opt-out preferences.

For code-first outbound calling, use a Foundry voice agent (Scenario 7).

Scenario 17: Intent discovery to decide what to automate next

User stories

  • As a contact center owner, I want data on which call reasons to automate next.

Implementation outline

  1. Enable Customer Intent Agent in Dynamics 365 Contact Center.
  2. Each sprint, take the top unautomated intents and add them as sub-agents to the harness agent.

Scenario 18: Fraud signal during an account takeover attempt

User stories

  • As a fraud analyst, I want risky calls stopped before any account change happens.

Events

SMS One Time Passcode, plus escalation.

Implementation outline

  1. In CCI, combine identity evidence, voice biometrics, fraud signals and MFA into an interaction outcome.
  2. On a risky outcome, require the SMS one-time passcode, then route to a specialist queue for human review.

Scenario 19: Live translation for representatives

User stories

  • As a German-speaking representative, I want to help a caller who only speaks Polish.

Implementation outline

  1. Enable live transcription and translation in Dynamics 365 Contact Center.
  2. Combine with Scenario 5: the AI handles the caller's language itself, and translation covers the human part of the call.

Scenario 20: After-hours callback by email

User stories

  • As a caller at 22:00 with a complex issue, I want a guaranteed follow-up rather than "call back tomorrow".

Events and tools

Escalate to Email, End of Conversation.

Implementation outline

  1. Collect a summary, preferred callback slot and consent.
  2. Use the Escalate to Email path to send it to the team mailbox.
  3. Confirm the next step in End of Conversation.

Scenario 21: Web or kiosk avatar for the same agent

User stories

  • As a website or branch visitor, I want to talk to a visual assistant instead of reading menus.

Implementation outline

  1. Use the Voice Live API avatar feature (standard or custom avatar synchronised with audio, WebRTC via session.avatar.connect).
  2. Reuse the same Foundry agent, tools and knowledge as the phone channel.
  3. Build the web or kiosk front end in custom code. Check avatar region availability.

Scenario 22: Internal IT and HR help desk line

User stories

  • As an employee, I want to reset my password or check my leave balance by calling an internal number from Teams.

Implementation outline

  1. Teams Phone resource account without a phone number: only users in your tenant can call it over VoIP from the Teams client.
  2. Use tags to transfer to the IT or HR call queue (Path A in Scenario 6).
  3. The Teams Phone channel uses "No authentication", so identify the caller from the Teams caller ID through a lookup.
  4. Keep sensitive actions such as password resets behind a separate verification step (for example, a one-time code to a registered device).

5. Planning notes

  • Preview status. The Customer Conversation harness, CCI, Foundry voice agents and the Copilot Studio Teams Phone integration are preview or prerelease features.
  • Tenant enablement. The Copilot Studio and Teams Phone Agent integration may need enablement through Microsoft support.
  • EU data residency. For standard-harness real-time agents, EU Data Boundary customers cannot use GPT-Realtime or GPT-Realtime-Mini because they need cross-geo processing. GPT-5-Chat (preview) supports in-region processing in the EU. Confirm the model and data location before go-live in Germany.
  • Cost. The Customer Conversation harness uses Copilot Credits for using, building, testing and evaluating. Large Evaluate runs count.
  • Biometrics and recording. Plan a DPIA, consent wording and a works council agreement (Germany) for recording and QA scoring of employees.
  • Latency. Generative orchestration on the Teams Phone channel (standard harness) can add 5 to 6 seconds, which is why classic orchestration is used there.
